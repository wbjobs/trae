# 异步Redis架构说明

## 问题背景

原始架构中，数据生成和异常检测在同一个事件循环中执行，当检测算法较慢时会导致数据积压和延迟。

## 新架构

```
┌─────────────────┐     ┌─────────────┐     ┌──────────────────┐
│  Data Generator │────▶│ Redis Stream│────▶│ Anomaly Worker   │
│  (每秒10条)     │     │  (缓冲队列) │     │  (批量处理100条) │
└─────────────────┘     └─────────────┘     └────────┬─────────┘
                                                     │
                                                     ▼
                                               ┌─────────────┐
                                               │ Redis Pub/Sub│
                                               │  (结果通道)  │
                                               └──────┬──────┘
                                                      │
                                                      ▼
                                               ┌──────────────┐
                                               │  WebSocket   │
                                               │  (推送前端)  │
                                               └──────────────┘
```

## 组件说明

### 1. config.py
全局配置，包括Redis连接参数、流名称、批次大小等。

### 2. data_generator.py
股票数据生成器，独立模块可复用。

### 3. anomaly_detector.py
异常检测器，支持批量检测（`detect_batch`方法），大幅提高处理效率。

### 4. main.py - 主服务进程
- **数据生成子进程**：每秒生成10条数据写入Redis Stream
- **Redis订阅协程**：订阅结果通道，将检测结果推送给WebSocket客户端
- **WebSocket服务**：管理客户端连接，广播实时数据

### 5. worker.py - 异常检测Worker进程
- 从Redis Stream批量读取数据（每次100条）
- 批量执行3-sigma异常检测
- 将结果发布到Redis Pub/Sub通道
- 使用Redis Consumer Group实现消息确认，保证数据不丢失

### 6. launch.py - 启动脚本
一键启动主服务和Worker进程。

## 性能优化点

1. **解耦**：数据生成和异常检测完全分离，互不阻塞
2. **批量处理**：Worker每次处理100条数据，NumPy向量化计算效率更高
3. **异步IO**：使用Redis Pipeline减少网络往返
4. **背压机制**：Redis Stream作为缓冲，可应对突发流量
5. **水平扩展**：可启动多个Worker进程分担负载（Consumer Group自动负载均衡）

## 数据流时序

```
时间轴:
0s:  Generator写入10条 → Stream
0.1s: Worker读取100条(如果有) → 批量检测 → 发布结果
0.2s: Subscriber接收结果 → WebSocket广播
1s:  Generator写入下一批10条 → Stream
...
```

平均延迟：~100-200ms (远低于1秒的数据流间隔)

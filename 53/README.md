# WebRTC 实时画板应用

一个基于 WebRTC 的实时协作画板应用，支持 P2P 连接和加密数据传输。

## 功能特点

- 🎨 实时同步绘制内容
- 🎨 多种颜色和笔刷大小选择
- 🔒 P2P 加密传输（XOR 对称加密）
- 📱 支持触摸设备
- 🏠 房间创建与邀请链接
- 🎤 实时语音聊天（独立音频流，不影响画板）
- 🔊 麦克风开关和音量指示器

## 技术栈

### 服务器端
- Node.js
- Express
- WebSocket (ws)

### 客户端
- React 18
- Vite
- React Router
- WebRTC API

## 快速开始

### 1. 启动信令服务器

```bash
cd server
npm install
npm start
```

服务器将在 `http://localhost:3001` 启动。

### 2. 启动前端应用

```bash
cd client
npm install
npm run dev
```

前端应用将在 `http://localhost:3000` 启动。

## 使用说明

### 用户 A（创建房间）
1. 打开 `http://localhost:3000`
2. 点击「创建新房间」
3. 复制生成的邀请链接
4. 将链接发送给用户 B

### 用户 B（加入房间）
1. 打开用户 A 发送的邀请链接
2. 或手动输入房间号加入

### 开始协作
- 双方连接成功后，即可开始在画板上绘制
- 所有绘制内容将实时同步给对方
- 可以选择不同颜色和笔刷大小
- 点击「清除画布」可清空双方画布

## 加密说明

应用使用预共享对称密钥进行 XOR 加密：
- 密钥定义在 `client/src/utils/crypto.js` 中的 `SHARED_SECRET`
- 所有通过 DataChannel 传输的数据都会被加密
- 接收方使用相同密钥解密

## 自动重连与状态同步

### 重连机制
- 当 DataChannel 因网络波动断开时，会自动尝试重连
- 重连间隔：2秒
- 最大重连次数：10次
- 重连过程中界面会显示"正在重连 (x/10)..."提示
- 重连成功后自动恢复连接并同步画布状态

### 状态同步机制
- 每个用户本地维护完整的绘制历史记录
- 新用户加入或重连成功后，会自动请求画布全量状态
- 对方收到同步请求后，发送完整的绘制历史
- 收到全量状态后，清空本地画布并重放所有历史绘制
- 支持的同步消息类型：
  - `sync-request`: 请求画布全量状态
  - `sync-response`: 响应全量状态请求
  - `full-state`: 画布全量状态数据
  - `draw`: 增量绘制操作
  - `clear`: 清除画布操作

## 测试方法

### 测试重连功能
1. 两个用户建立连接并开始绘制
2. 断开其中一个用户的网络（如禁用网卡）
3. 观察界面显示"正在重连..."提示
4. 恢复网络连接
5. 验证重连成功后，双方画布状态一致

### 测试新用户加入同步
1. 用户A创建房间并绘制一些内容
2. 用户B加入房间
3. 验证用户B的画布自动同步显示用户A已绘制的所有内容

## 语音聊天功能

### 功能说明
- 语音聊天与画板数据使用同一个 WebRTC 连接，但通过不同的通道传输
- 音频流使用 RTCPeerConnection 的 `addTrack` API 传输
- 画板数据使用 DataChannel 传输
- 两者互不阻塞，独立工作

### 使用方法
1. 双方建立 P2P 连接后，点击「🎤 点击开启语音聊天」展开音频面板
2. 点击「🎤 开启麦克风」按钮，浏览器会请求麦克风权限
3. 授权后即可开始语音对讲
4. 可以看到双方的麦克风状态和音量指示器
5. 再次点击按钮可以关闭麦克风

### 音频特性
- 回声消除 (echoCancellation)
- 噪音抑制 (noiseSuppression)
- 自动增益控制 (autoGainControl)
- 实时音量显示

## 注意事项

- WebRTC 需要 STUN 服务器协助穿透 NAT，应用使用了 Google 的公共 STUN 服务器
- 在严格的网络环境下可能需要 TURN 服务器
- 建议使用 HTTPS 协议（生产环境）
- 两个用户需要在不同的浏览器/设备上测试
- 绘制历史会占用内存，长时间大量绘制可能影响性能
- 语音聊天需要浏览器麦克风权限
- 建议使用耳机以避免回声
